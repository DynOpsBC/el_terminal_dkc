# BCWMS Print Agent

Production-oriented Windows tray agent for the BCWMS direct Azure print path.
It keeps the simple ELOG operating model—refresh printers, sync, leave the app
in the tray—without embedding Azure credentials in source or an executable.

## Runtime flow

```text
Business Central / terminal
  -> private Blob (payload)
  -> print-jobs-queue (sessionId = canonical stationId, metadata only)
  -> this Windows agent
  -> PdfiumViewer -> Windows PDF spooler
     or byte-for-byte ZPL/ESCPOS/RAW -> Windows RAW spooler
  -> durable local journal + status outbox
  -> printer-status-queue -> Business Central
```

The agent processes exactly one canonical station session. The recommended ID
is `TENANT.COMPANY.WAREHOUSE.STATION`, for example
`CONTOSO.CRONUS.MAIN.PACK01`. It must contain exactly four uppercase canonical
segments; every segment is 1–32 characters and may contain `A-Z`, `0-9`, `_`
or `-`.

The Azure entities are deliberately fixed:

- session-enabled queue `print-jobs-queue`;
- non-session queue `printer-status-queue`;
- private Blob container `print-jobs`;
- queue policy `agent-listen-jobs` with Listen only;
- queue policy `agent-send-status` with Send only;
- Blob container-scope (`sr=c`) stored policy `agent-read`, or a container SAS
  whose only permission is `r`; account SAS tokens are rejected.

## Day-to-day UI

The **Yazıcılar** tab provides:

- station ID and stable agent ID;
- installed Windows printer discovery;
- separate label and PDF document selection;
- label format (`ZPL`, `ESCPOS`, `RAW`);
- Windows RAW through an installed USB/network Windows printer queue;
- **Yazıcıları Yenile**, **Buluta Eşitle**, local label test and local PDF test;
- **Belirsiz İşleri İncele** for explicit crash/timeout reconciliation;
- live logs and connection state.

The built-in BCWMS LP/item/bin actions in this repository generate **ZPL**.
Choose ZPL for those terminal actions. ESCPOS and RAW are supported transport
formats for custom integrations that actually enqueue those payload formats; a
local ESCPOS/RAW test alone does not make the built-in ZPL labels compatible.

Closing the window hides it in the system tray. **Çıkış** in the tray menu is
the explicit process shutdown. Autostart is per Windows user, does not require
administrator rights, and preserves access to that user's installed printers
and DPAPI secrets.

The **Azure Ayarları** tab imports the agent-only
`print-agent.runtime.secrets.json` generated by
`direct-print-azure/scripts/Initialize-Configuration.ps1`. The importer reads
only the v1 agent/routing fields (never BC send/listen secrets), validates the station/container, fills the
form and displays SAS expiry. It never changes or deletes the source file.
After a successful save, move/delete that plaintext file according to the
organization's secret-handling policy.

All saved settings—including both Service Bus connection strings and the Blob
SAS—are encrypted at rest with Windows DPAPI `CurrentUser` in:

```text
%LOCALAPPDATA%\DynOps\BCWMS Print Agent\agent.config.dpapi
```

Do not copy this file between Windows users; each user must import and save its
own settings.

## Install and configure

Prerequisites:

- a currently supported Windows 11 x64 release or Windows Server 2022/2025 x64
  with an interactive user session (Windows 10 is limited to Microsoft-supported
  LTSC/Enterprise releases; verify the current
  [official .NET 10 OS matrix](https://learn.microsoft.com/dotnet/core/install/windows));
- the required Windows printer drivers already installed;
- outbound HTTPS/AMQP-over-WebSockets access to Azure;
- provisioned `direct-print-azure` resources and its
  `.local/print-agent.runtime.secrets.json` file.

The ZIP is self-contained; no .NET runtime installation is required.

1. Extract `BCWMS-Print-Agent-win-x64.zip` without changing its structure.
2. Run the following in normal (non-administrator) PowerShell:

   ```powershell
   Set-ExecutionPolicy -Scope Process Bypass
   .\BCWMS-Print-Agent-win-x64\installer\install.ps1
   ```

3. In the automatically opened panel, go to **Azure Ayarları** and choose
   **Print Agent Secrets İçe Aktar** for `print-agent.runtime.secrets.json`.
4. In **Yazıcılar**, choose different label and document queues. For a USB
   or network Zebra/receipt printer, install its Windows driver/queue first;
   v1 deliberately supports only `WindowsRaw`.
5. For the repository's built-in terminal labels choose `ZPL`; choose `ESCPOS`
   or `RAW` only for a custom producer that emits that exact format. Click
   **Ayarları Kaydet ve Bağlan**.
6. Click **Etiket Testi** and **Belge Testi**. These are local tests and do not
   require a healthy Service Bus connection after valid settings have been
   saved.
7. Click **Buluta Eşitle**. Only the selected label/document logical printers
   are advertised to BC. Their stable IDs have the BC `Code[20]`-safe form
   `P` + 16 uppercase hexadecimal characters.
8. Run `direct-print-azure/scripts/Send-SmokeTest.ps1` with the printer ID and
   exact name shown/synchronized by the agent. Confirm physical output; this raw
   Azure smoke has no BC queue row, so its valid orphan `JobResult` is consumed
   without a BC `Sent` record. Then send a real BC/terminal job and confirm its
   `Queued → Dispatched → Sent` transition before enabling production actions.

The initial snapshot and heartbeat prove only the status-send path. The UI stays
in **smoke job bekleniyor** state until a Service Bus session is acquired. A
real cloud smoke job is required to prove the Listen credential, Blob read path,
isolated print helper, Windows spooler and physical printer together.

## Job contract v1

UTF-8 JSON body (lower camel case):

```json
{
  "schemaVersion": 1,
  "jobId": "11111111-2222-3333-4444-555555555555",
  "tenantId": "CONTOSO",
  "companyId": "CRONUS",
  "stationId": "CONTOSO.CRONUS.MAIN.PACK01",
  "printerId": "P0123456789ABCDEF",
  "printerName": "ZDesigner ZD220-203dpi ZPL",
  "format": "ZPL",
  "copies": 1,
  "blobName": "jobs/CONTOSO.CRONUS.MAIN.PACK01/11111111-2222-3333-4444-555555555555.zpl",
  "payloadSha256": "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA",
  "payloadSize": 12345,
  "createdAtUtc": "2026-08-11T10:00:00Z"
}
```

Required broker metadata:

- `SessionId` = exact `stationId`;
- `MessageId` = `jobId` GUID;
- `CorrelationId` = `jobId` GUID;
- `ContentType` = `application/json`.

Validation rules:

- `schemaVersion` is exactly `1`; required field names/types and value bounds
  are strict. Unknown v1 fields are ignored for additive compatibility.
- `jobId` is canonical lowercase GUID D format.
- `printerId` is exactly `P[0-9A-F]{16}` (17 characters, within BC `Code[20]`).
- `format` is `PDF`, `ZPL`, `ESCPOS`, or `RAW`; `copies` is 1–10.
- `blobName` is exactly
  `jobs/{stationId}/{jobId}.{pdf|zpl|escpos|raw}`. A URL, foreign station,
  traversal segment, backslash or alternate job path is rejected.
- payload length must equal `payloadSize`, remain under the 50 MB hard maximum,
  and match canonical uppercase SHA-256 hex.
- PDF must begin with `%PDF-`; it is parsed/rendered in a killable child process
  with current non-V8 PDFium 152, at 300 DPI, at most 200 pages, 25 million
  pixels/page and 500 million pixels/job.
- each PDF MediaBox becomes that page's Windows `PaperSize` (points to 1/100
  inch). If the driver silently falls back to another size, printing fails with
  an actionable error; define custom media such as 100×150 mm in the driver.
- tenant, company, station, logical printer ID and Windows printer name must
  all match the local allowlist exactly (printer name is case-insensitive).
- non-PDF jobs must exactly match the configured label language; for example,
  an `ESCPOS` job is never forwarded to a station configured as `ZPL`.

No SAS, connection string or arbitrary document URL is carried in a job.

## Status contracts v1

Every message sent to the non-session `printer-status-queue` has:

```json
{
  "schemaVersion": 1,
  "messageType": "PrinterSnapshot | Heartbeat | JobResult",
  "messageId": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
  "tenantId": "CONTOSO",
  "companyId": "CRONUS",
  "stationId": "CONTOSO.CRONUS.MAIN.PACK01",
  "agentId": "11111111-2222-3333-4444-555555555555",
  "sentAtUtc": "2026-08-11T10:00:00Z",
  "agentVersion": "1.0.0"
}
```

Additional `PrinterSnapshot` fields:

```json
{
  "printers": [
    {
      "printerId": "P0123456789ABCDEF",
      "printerName": "ZDesigner ZD220-203dpi ZPL",
      "format": "ZPL",
      "status": "Online",
      "isDefault": false
    }
  ],
  "selection": {
    "labelPrinterId": "P0123456789ABCDEF",
    "documentPrinterId": "PABCDEF0123456789",
    "labelTransport": "WindowsRaw"
  }
}
```

Only the selected label and document printers are included. A selected printer
that disappeared from Windows remains in the snapshot as `Offline`, preserving
its logical ID until the operator changes the selection.
The ID is stable while the Windows queue name remains the same. Renaming or
recreating a Windows queue intentionally creates a new logical ID; sync it and
update the BC printer mapping before dispatching new jobs.

`Heartbeat` adds `status` and nullable `lastJobId`. `JobResult` adds `jobId`,
`printerId`, `printerName`, `format`, Boolean `success`, a maximum 500-character
`message`, `completedAtUtc`, and `attempt`.

Status messages have no `SessionId`. `Subject` is `messageType`; a JobResult's
correlation ID is `jobId`, otherwise it is `agentId`. Application properties
contain `schemaVersion`, `messageType`, `tenantId`, `companyId`, and
`stationId`.

Heartbeat defaults to 300 seconds. Heartbeats have a short bounded TTL and
snapshots expire after 15 minutes so stale `Online` state cannot be replayed
days later. `Starting` means status Send works but a jobs session has not yet
proved Listen/routing; `Degraded` means the jobs receiver/credential is
unhealthy. Printer selection and runtime health remain separate concepts.

## Delivery and duplicate behavior

Delivery is at least once, but physical output is guarded at-most-once. After
download/hash/PDF pre-validation and immediately before launching the print
helper, the agent durably records an `InProgress` intent containing a fingerprint
of every immutable job field. Only helper exit success changes it to `Completed`
and allows Service Bus completion. A matching completed redelivery skips paper;
a changed replay is dead-lettered.

A crash, cancellation, helper timeout (30-minute hard limit), or journal failure
after `InProgress` is never auto-reprinted. It becomes `OutcomeUncertain`, is
dead-lettered and requires physical inspection. Use **Belirsiz İşleri İncele**:
mark it Completed only after confirming paper; if no paper exists, keep the
intent and resend from BC with a **new JobId**. The journal never silently drops
unresolved intents. **Completed işaretle** only reconciles the agent's local
dedupe journal; it does not rewrite an earlier BC Failed state or remove a DLQ
message. Reconcile that BC/DLQ record separately under the site's incident
procedure. Corrupt journal/outbox files fail closed.

Ordinary transient errors before the durable intent use bounded exponential
backoff (5/15/45/120 seconds with jitter) until `MaxDeliveryAttempts` (default
5). Expired/rejected Blob credentials pause the locked session and publish
`Degraded` instead of mass-DLQ; import renewed agent secrets and restart.

Successful/failed JobResult messages use a separate atomic local outbox. A
temporary status-queue outage therefore does not hold the physical job open or
cause a reprint. The heartbeat loop retries the outbox and removes a result only
after Service Bus accepts it.

Printer discovery, PDF validation/rendering and physical spool calls run in the
same executable's isolated helper mode. Hung WMI/native driver code is killed at
its bounded timeout without wedging the tray/Service Bus process. RAW short
writes are continued until all bytes are accepted; zero progress is an error.

## Build, test and package

With .NET 10 SDK and PowerShell 7+ for packaging:

```powershell
dotnet test .\BCWMS.PrintAgent.sln -c Release -p:EnableWindowsTargeting=true
.\scripts\publish-win-x64.ps1
```

The publish script runs tests, creates a self-contained multi-file `win-x64`
deployment with root `pdfium.dll`, verifies every packaged file and scans for
accidentally packaged plaintext secrets,
vendors the complete PDFium license bundle and writes:

```text
dist\BCWMS-Print-Agent-win-x64\
dist\BCWMS-Print-Agent-win-x64.zip
```

The installer verifies the exact manifest (rejecting extra files), stages and
re-hashes the full install, then swaps directories with rollback. The generated
ZIP/exe/scripts are **not Authenticode-signed in this workspace**. For a signed
customer release, pass a Windows signing hook before manifest creation:

```powershell
.\scripts\publish-win-x64.ps1 -SigningScript .\ci\sign-print-agent.ps1
```

The hook receives `-PackageRoot <staging-folder>`, must sign at least
`app\BCWMS.PrintAgent.exe` and every `installer\*.ps1`, and return success. The
publisher verifies those signatures, then creates hashes and the ZIP with
`authenticodeSigned=true`. Never sign or modify packaged files after manifest
creation; that correctly makes the installer reject their stale hashes.

## Data, logs and recovery

Per-user files:

```text
%LOCALAPPDATA%\DynOps\BCWMS Print Agent\
  agent.config.dpapi       DPAPI CurrentUser settings
  completed-jobs.json      duplicate journal
  status-outbox.json       pending JobResult messages
  logs\agent-YYYYMMDD.log  sanitized logs, 14-day retention
  spool\                   temporary payloads
```

Secrets/SAS query values are redacted from logs. Payload content is never
logged. Do not manually delete the journal or outbox during an incident; first
stop the agent and preserve the files for diagnosis.
Only one tray/worker owner can run per Windows user profile across RDP sessions;
a SID-scoped `Global\` mutex protects the shared DPAPI/journal/outbox files.

Least-privilege credentials limit blast radius but do not create sender
identity inside a shared queue. If an authorized queue-send credential itself
is compromised, the agent cannot cryptographically distinguish that sender
from BC; rotate the affected policy immediately. Keep one BC environment and
company in the deployment trust zone, protect the BC send/blob-write secrets,
and monitor dead-letter/job-result traffic.

Uninstall (settings/journal retained by default):

```powershell
& "$env:LOCALAPPDATA\Programs\BCWMS Print Agent\installer\uninstall.ps1"
```

Full removal is explicit and irreversible:

```powershell
& "$env:LOCALAPPDATA\Programs\BCWMS Print Agent\installer\uninstall.ps1" `
  -RemoveUserData
```

## Verification boundary

The portable core tests cover contract parsing, station/blob constraints,
ESCPOS, strict enums/SHA, queue/SAS policy validation, paper geometry/render
budgets, helper protocol/timeouts, RAW short-write progress, retry boundaries,
two-state journal recovery and durable outbox replay. Cross-compilation verifies
the .NET 10 Windows x64 executable and current non-V8 PDFium native file. Final
acceptance still requires a Windows machine, real Azure resources, installed
printer drivers, and physical tests for ZPL/ESC-POS/RAW plus A4, Letter,
100×150 mm and mixed-page PDFs. A non-Windows host cannot claim paper output.
